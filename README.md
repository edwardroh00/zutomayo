## 2027 홀투어 일정·지도 · 2026.10.16

기존 [홈페이지의 투어 일정](https://zutomayo-my-room-1014.spunky-gnat-0005.chatgpt.site/#tour)에 2027.01.15~05.23, 23개 공연장·36회 일정을 추가했습니다. 일정과 입장·시작 시간은 사용자가 제공한 포스터 기준이며 공식 웹 원문 대조 미완료 상태를 표시합니다. 기존 역대 일정 275건과 합해 카탈로그는 311건입니다.

- 갈 공연·티켓 확보 체크, 월·도시·선택 일정 필터, 선택 일정의 JST 캘린더 다운로드
- 공연장별 구글지도, 사진·리뷰 및 길찾기 링크. 내부 사진 제공 여부는 구글지도에 등록된 사진에 따라 달라집니다.
- 23개 공연장을 한눈에 보는 별도 OpenStreetMap 핀 지도. 위치별 출처는 `data/tour-venues.json`에 보존했습니다.
- 아티스트 표기는 **즛토마요**로 통일하고, 공연·공연장·지역은 한국어를 메인으로, 원문을 작은 글자로 표시합니다. 한국어 번역·음역은 표시용이며 공식 한국어 번역으로 인증한 정보가 아닙니다.
- 체크 기록은 기존 브라우저 프로필·JSON 백업에 함께 저장됩니다. 예정 공연은 공연일 전 관람·청취 통계에서 제외하며 기존 백업도 읽을 수 있습니다.

`node scripts/check-tour.mjs`로 일정·좌표·필터·백업 호환·예정 공연 집계 제외·캘린더를 검증합니다. `npm run check`에도 포함했습니다. Leaflet 1.9.4는 `vendor/leaflet/`에 라이선스와 함께 포함했습니다.

프로젝트의 최종 방향은 **개인화된 즛토마요 덕질 홈페이지**입니다. 첫 버전은 본인용 굿즈 보유·사이즈, 관람한 공연, 라이브에서 들어본 곡과 개인 통계를 한곳에 모읍니다. 목표·집계 기준은 [프로젝트 메모리](./project_memory/README.md)에 기록했습니다.

## GitHub에 푸시

GitHub에서 빈 저장소를 만들고 실제 저장소 URL로 아래 `OWNER/REPOSITORY`를 바꿉니다. 초기 README나 라이선스를 생성한 기존 저장소에는 바로 실행하지 말고 먼저 이력을 확인하세요.

```powershell
git add .
git commit -m "Add Korean ZUTOMAYO Nara concert guide"
git branch -M main
git remote add origin https://github.com/OWNER/REPOSITORY.git
git push -u origin main
```

이미 `origin`이 있으면 `git remote add`는 생략합니다. 푸시에는 이 컴퓨터의 GitHub 인증이 필요합니다. 공개 저장소에는 프로젝트 파일만 올리고 계정 토큰, 티켓, 여권, 개인 일정은 넣지 마세요.

## GitHub Pages 공개

저장소 **Settings → Pages → Build and deployment**에서 아래와 같이 설정합니다.

1. Source: **Deploy from a branch**
2. Branch: **main**, 폴더: **/(root)**
3. **Save**

공개 주소는 일반적으로 `https://OWNER.github.io/REPOSITORY/`입니다. 상대 경로를 사용하므로 저장소 이름에 따른 하위 경로에서도 동작합니다. GitHub Pages 공개 설정을 활성화하기 전까지 푸시만으로 웹사이트가 공개되지는 않습니다.

GitHub 공식 문서: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site
